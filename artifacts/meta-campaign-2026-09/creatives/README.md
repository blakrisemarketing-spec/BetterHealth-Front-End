# Meta creatives, September 2026

Static images for the two September campaigns in [`../ad-copy.md`](../ad-copy.md)
(BHA Test Panels and BHA Lead Magnets). 22 creatives, each rendered at 4:5 for feed
(the upload set) and 9:16 for stories and reels. 68 files in total, 5995 KB combined,
every file under 600 KB.

Ids match the `utm_content` values in the ad copy (`<slug>-a` is the card, `<slug>-b`
the statement hook). Prices are exclusive of VAT and every price on an image says so.

## Re-rendering

Everything is generated from a data table in `build.mjs` plus three templates in
`templates/` (`p-card.html`, `g-card.html`, `hero.html` for both statement modes) and
`templates/base.css`. Run from this directory:

```bash
cd "artifacts/meta-campaign-2026-09/creatives"
node build.mjs                                   # all 22 creatives, both sizes (44 files)
node build.mjs --size 4x5                        # feed set only
node build.mjs --only panorama-a,shield-b        # a subset, both sizes
node build.mjs --html-only                       # rewrite src/ without rendering
```

The build needs Google Chrome at `/Applications/Google Chrome.app` (override with
`CHROME_PATH`) and imports `puppeteer-core` from the BetterHealth-Media repo at
`/Users/greatdamzi/Documents/01. GitHub/BetterHealth-Media/node_modules`. It writes
`manifest.json` (id, mode, size, file, KB, fitted font sizes and line counts).

To render a single source by hand:

```bash
# PNG, via the Media renderer
node "/Users/greatdamzi/Documents/01. GitHub/BetterHealth-Media/scripts/render-social-still.mjs" \
  "$PWD/src/panorama-a-4x5.html" "$PWD/../../../public/ads/2026-09/panorama-a-4x5.png" 1080 1350

# JPEG (photo variants), via the sibling script here
node render-jpg.mjs src/panorama-b-4x5.html ../../../public/ads/2026-09/panorama-b-4x5.jpg 1080 1350 88
```

## Layout rules baked into the templates

- Quicksand only (variable 300 to 700, `assets/Quicksand.woff2`), sage `#6B8E7F` as the
  accent, deep text `#2B3A3A`, cream `#F5F3EE`, border `#E0DCD5`, dark `#0F1724`.
- Logo 300 px wide on the cream cards; 280 px inside the cream pill on the dark heroes;
  222 px on the 4:5 photo heroes so the pill clears the woman's hand and the tablet edge.
- 90 px side margins and 84 px top and bottom on 4:5. On 9:16 the whole composition sits
  in the middle 1180 px (370 px top and bottom), so the story UI never covers key copy.
  On the 9:16 photo heroes the photo owns the top 900 px and the logo pill moves below it.
- Statements auto-fit: the in-page `__fit` script shrinks from 124 px (84 px on the 4:5
  photo heroes) until the block is at most four lines and nothing overflows. Headlines
  auto-fit to two lines (P-CARD) or three (G-CARD). Fitted sizes are in `manifest.json`.
- Hyphenated tokens ("7-Day", "check-up") never break at the hyphen. No em dashes.
- Statement markup in the data table: `*phrase*` = sage accent, `|` = forced line break.

## Departures from the brief, and why

- `cardion-b` and `home-blood-pressure-guide-b`: the statement is two sentences and ran
  past four lines at hero size, so the first sentence is the big statement and the second
  is a 58 px sage sub-line. No words were changed.
  - `cardion-b`: "1 in 3 adults in Ghana has high blood pressure." + "Fewer than half know."
  - `home-blood-pressure-guide-b`: "One raised reading is not a diagnosis." + "Seven days is a pattern."
- `which-test-a` bar text is "Two minutes, free, no account needed." (from the approved
  primary text) rather than the WhatsApp line, because the quiz runs on the page and its
  bullets already say "No account, no sales call".
- The PDF mocks use placeholder rules instead of numbers so no reference range appears
  in tiny type on an ad; the quiz mock uses lettered option pills for the same reason.
- Page counts on the G-STATE chips were corrected on 2026-09-02 to the real PDF lengths:
  `know-your-numbers-b` 3 pages, `home-blood-pressure-guide-b` 2 pages,
  `read-your-results-b` 3 pages (`blood-sugar-log-b` stays 4, `family-health-map-b` stays 2).
  The ad-copy descriptions still quote the earlier counts for those three guides.

### The three tool mocks

`build.mjs` gains `genotype`, `risk` and `heartage` in `MOCKS`, plus a `TOOL_MOCKS` set
that switches the card chrome. Creative rows carry `badge`, `button` and `bar`, which
already existed on `G-CARD`; the badge doubles as the tag inside the mock head.

- `genotype`: two labelled selects ("You: AS", "Partner: AS") over a three-segment odds
  bar at 25 / 50 / 25 with AA, AS and SS captions. The split is Mendelian, which is the
  arithmetic the calculator does.
- `risk`: the line "Your score: 13 of 26" over a five-band scale (Low, Slightly raised,
  Moderate, High, Very high) with the third band filled and a slider marker on it.
- `heartage`: "52" under an "Estimated heart age" label, "Your age 44" beneath it, then
  two factor rows (Blood pressure, Smoking) with sage bars.

The numbers are interface furniture at mock scale, not results and not population
statistics. As with the PDF mocks, no reference range, threshold or risk percentage
appears anywhere on the twelve images.
